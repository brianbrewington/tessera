
# Social Network Evolution Simulator - Data Schema

This document describes the JSON schema used for importing and exporting simulation data. The application uses this structure to bootstrap the simulation state.

**Version:** 1.1
**Encoding:** UTF-8

## Root Object

The root of `simulation_data.json` contains:

```json
{
  "participants": [ ... ],
  "projects": [ ... ],
  "topics": [ ... ],
  "logs": [ ... ]
}
```

## Data Types & Technical Specifications

*   **UUID**: All `id` fields must be valid **UUID v4** strings.
*   **Timestamp**: All `timestamp` fields are **Integer** representing **Unix Epoch Milliseconds** (UTC).
*   **Embeddings**: The `embedding` field is an array of floating-point numbers.
    *   **Model**: Google Gemini `text-embedding-004`
    *   **Dimensionality**: 768 dimensions
    *   **Metric**: optimized for Cosine Similarity
*   **Graph Topology**: The graph is **Directed**. A relationship object located inside Entity A targeting Entity B represents a directed edge $A \to B$. Inverse relationships must be explicitly defined on Entity B if they exist.

## Entity Types

### 1. Participant (Person)
Represents a user in the network.

```json
{
  "id": "uuid-v4-string",
  "name": "String (Title Case)",
  "profileText": "String (Raw text from original import)",
  "interests": ["String", "String"],
  "relationships": [ ...Relationship Objects... ],
  "aiContext": "String (Markdown formatted summary of past interactions, maintained by the AI agent)"
}
```

### 2. Project
Represents a project, idea, or initiative. Can act as an AI agent (Oracle) in conversations.

```json
{
  "id": "uuid-v4-string",
  "name": "String (Project Title)",
  "ownerId": "uuid-v4-string (Reference to Participant.id)",
  "description": "String (1-sentence summary generated by AI)",
  "tags": ["String", "String"],
  "relationships": [ ...Relationship Objects... ],
  "aiContext": "String (Markdown formatted summary)"
}
```

### 3. Topic (Field of Knowledge)
Represents a concept, field of study, or bridge topic.

```json
{
  "id": "uuid-v4-string",
  "name": "String (Topic Name)",
  "description": "String (Definition or summary)",
  "relatedLinks": [
    { "title": "String", "url": "String (Valid URI)" }
  ],
  "embedding": [0.041, -0.012, ...], 
  "relationships": [ ...Relationship Objects... ],
  "aiContext": "String (Markdown formatted summary)"
}
```

## Relationships
All entities share a common relationship structure.

```json
{
  "targetId": "uuid-v4-string",
  "targetName": "String (Cached name of target for display)",
  "targetType": "PERSON" | "PROJECT" | "TOPIC",
  "type": "RelationshipEnum",
  "context": "String (Reason for connection generated by AI)"
}
```

### Relationship Enums (Semantics)
*   `KNOW`: Weak connection. Entities have interacted or are aware of each other.
*   `FOLLOW`: Unidirectional interest. Source follows Target.
*   `OWN`: Source (Person) created/owns Target (Project).
*   `BELONGS_TO`: Inverse of OWN. Target (Project) belongs to Source (Person).
*   `SYNERGY`: Bi-directional compatible link between two Projects.
*   `INTERESTED_IN`: Source (Person) has expressed curiosity in Target (Topic).
*   `BRIDGE`: A conceptual link between two Topics (e.g., "Bioinformatics" bridges "Biology" and "CS").

## Logs (Conversation History)
Stores the transcripts and outcomes of interactions.

```json
{
  "participants": ["uuid-1", "uuid-2"],
  "timestamp": 1715000000000,
  "transcript": [
    {
      "speakerId": "uuid-1",
      "speakerName": "String",
      "text": "String (Dialogue)"
    }
  ],
  "actions": [
    {
      "participantId": "uuid-1",
      "newRelationships": [ ...Relationship Objects... ],
      "suggestedIntroductions": ["String (Name)"]
    }
  ]
}
```

## Import Instructions
1.  **JSON Import**: Zip a single file named `simulation_data.json` matching this schema.
2.  **Raw Text Import**: Zip a folder of `.txt` files.
    *   **Filename**: Becomes `Participant.name`.
    *   **Content**: Becomes `Participant.profileText`.
    *   *Note*: Importing raw text triggers the AI Enrichment pipeline (Profile Extraction -> Project Generation -> Topic Clustering). Importing JSON skips enrichment and loads the state directly.
