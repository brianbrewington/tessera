# Dream Weaver v2: Narrative Dynamics & Dream Walking

## 1. Overview
This design expands the "Dream Weaver" from a simple pairwise association tool into a **Generative Narrative Engine**. Instead of finding single insights between two concepts, the system will select a "Cast of Characters" (Nodes) and weave a complex dream story involving them. This story is then treated as a new source of truth, from which new functionality and concepts are extracted.

## 2. The "Dream Walker" Selection Algorithm
We need to select a set of nodes $\{ S, n_1, n_2, ... n_k \}$ to participate in the dream.

### 2.1 Parameters
-   **Cast Size ($k$)**: Randomly inclusive between 2 and 5 additional nodes (Total 3-6).
-   **Chaos Factor ($\epsilon$)**: Probability (e.g., 0.3) of picking a random node vs. a connected node.

### 2.2 The Algorithm
1.  **Select Seed ($S$)**: Source node, user-selected or auto-selected.
    -   *Auto-Select Bias*: Heavily favors **Recency** (Nodes created/modified in the last 24h).
2.  **Assemble Cast**:
    -   Initialize `DreamSet = { S }`.
    -   While `|DreamSet| < TargetSize`:
        -   Roll Chaos Die ($d \in [0,1]$).
        -   **If $d > \epsilon$ (Walk)**: Pick a random neighbor of *any node currently in DreamSet* (BFS layer 1). This simulates "Association".
        -   **If $d \le \epsilon$ (Teleport)**: Pick a purely random node from the entire graph. This simulates "Random firing" or "Scene switching".
    -   Ensure uniqueness.

### 2.3 Dream Chaining ("The Tail")
To create coherent "Dream Sequences" (REMs), the system supports **Chaining**.
-   **Input**: `PreviousDream` (ContextNode).
-   **Mechanism**:
    1.  **Sticky Seed**: The `Seed` for Dream $N$ is set to the `DreamNode` of Dream $N-1$ (or a random Concept generated by it).
    2.  **Narrative Prompt**: The LLM prompt is updated to include the previous context:
        > "The previous dream ended with: '[Summary of Dream N-1]'. Continue the thread..."
-   **Effect**: This creates a "Tail" where ideas morph over time (e.g., Coffee Mug -> Recursive Coffee -> Recursive Universe -> The Big Bang).

## 3. Generative Pipeline

### 3.1 Phase 1: The Weaving (Narrative Generation)
**Input**: List of Nodes (Text + Type).
**Prompt**:
> "You are the Dream Weaver.
> **Previous Context**: [Optional 1-sentence summary of the last dream]
>
> The following Concepts, People, and Memories have appeared in the subconscious:
> - [Person] Alice
> ...
>
>
> Weave a vivid, surreal, and coherent **Dream Narrative** (1-2 paragraphs) that connects these elements.
> If a previous context exists, weave it in based on its 'fading' level:
> - Strong: It is a direct continuation.
> - Weak: It is a distant echo or flashback.
> The story should be metaphorical and fearlessly imaginative. 
> Treat the concepts as characters or physical objects interacting in a dreamscape. 
> Do not explain the connection; just tell the story."

**Output**: A raw text block (The Narrative).

### 3.2 Phase 2: Crystallization (Schema Update)
Create a new **ContextNode** for the Dream.
-   **Type**: `DREAM` (New Enum ID: 6).
-   **Text**: The generated narrative.
-   **Edges**: Link *from* the `DreamSet` nodes *to* the `DreamNode`.
    -   Type: `APPEARED_IN`.
    -   Weight: 1.0.

### 3.3 Phase 3: Lucid Extraction (Feedback Loop)
Treat the *Dream Narrative* as if it were a new user input text (Ingestion).
1.  **Extract**: Run the standard `extractEntities` methodology on the Dream Text.
2.  **Concepts**: Identify *new* concepts or implications invented by the dream.
    -   *Example*: Dream invents "Recursive Coffee Algorithms".
3.  **Graph Update**:
    -   Create `CONCEPT` nodes for the new items.
    -   Link them *to* the `DreamNode` (Origin).
    -   Link them *to* existing graph nodes if valid (e.g., "Recursive Coffee" connected to "Coffee Mug").

## 4. Temporal Dynamics: Transience & Reinforcement

### 4.1 Dream Transience (Fast Decay)
Dreams are fleeting. A `DREAM` node represents a transient activation state.
-   **Metric**: `strength` (Float 0.0 - 1.0).
-   **Decay Function**: **Fast Decay**.
    -   Half-life: ~5-10 minutes (configurable).
    -   Formula: $W_t = W_0 \cdot e^{-\lambda_{fast} t}$
-   **Role**: This weight determines the "Stickiness" (Probability) of this dream feeding into the *next* dream (Chaining). A dream from 1 hour ago (0.01 weight) is unlikely to chain. A dream from 2 minutes ago (0.8 weight) is highly likely.

### 4.2 Node Reinforcement (Slow Decay)
Core concepts and memories are persistent but fade if unused.
-   **Metric**: `strength` (Float 0.0 - 10.0+).
-   **Reinforcement**: When a Node creates/participates in a dream, its strength is **boosted** (e.g., +1.0).
-   **Decay Function**: **Slow Decay**.
    -   Half-life: ~30 days.
    -   Formula: $W_t = W_0 \cdot e^{-\lambda_{slow} t}$
-   **Motivation**: This ensures that frequently dreamt-of concepts become "Core Memories" (Long-term retention), while one-off oddities eventually fade.

### 4.3 Narrative Influence
The `strength` of the Previous Dream Node scales its influence on the prompt:
-   **High Strength (>0.7)**: "The previous dream is vivid in your mind..."
-   **Low Strength (<0.3)**: "You have a vague, fading sense of..." (or omitted entirely).

## 5. Proto Schema Updates (`context.v1.proto`)

### 4.1 New Node Type
```protobuf
enum NodeType {
  // ... existing
  INSIGHT = 5;
  DREAM = 6; // [NEW] Narrative container
}
```

### 4.2 New Edge Types
We can stick to `RELATED_TO` with specific labels, or standard string types:
-   `APPEARED_IN`: Existing Concept -> Dream
-   `ORIGINATED_FROM`: New Dream Concept -> Dream

## 5. Interaction Flow (UI)
1.  **Trigger**: User clicks "Deep Sleep" (or selects a Seed -> "Dream").
2.  **Visualizer**:
    -   Highlights the Seed.
    -   "Walks" (animates) to neighbor nodes.
    -   "Teleports" (flashes) to random nodes.
    -   Selection finalized (GLOWING group).
3.  **Synthesis**:
    -   System generates Narrative.
    -   **Dream Node** appears in center of group.
    -   **New Concept Nodes** burst out from the Dream Node.

## 6. Implementation Steps
1.  **Update Proto**: Add `DREAM` type.
2.  **Update `DreamWeaverService.ts`**:
    -   Implement `dreamWalk(seedId)` selector.
    -   Implement `weaveNarrative(nodes[])` LLM call.
    -   Refactor `synthesize` to support the multi-phase pipeline.
3.  **Update Extraction**: Ensure `extractEntities` can be called programmatically on string content without full "Ingestion" overhead (or reuse `addContext` with a special flag).

## 7. Testing Strategy
To support these dynamics, we need specific verification tests:

### 7.1 Unit Tests (`dream_decay.test.ts`)
1.  **Fast Decay verification**: Create a Dream Node, mock time passing (10 mins), verify `strength` drops significantly (< 50%).
2.  **Slow Decay verification**: Create a Concept Node, mock time passing (10 mins), verify `strength` remains stable (> 99%).
3.  **Reinforcement**: Verify that participating in a dream boosts a Concept Node's strength.

### 7.2 Integration Tests (`dream_chaining.test.ts`)
1.  **Chain Probability**: Run a simulation of 100 dream steps. Verify that consecutive dreams are more likely to link when the interval is short vs. long.
2.  **Narrative Continuity**: (Manual/LLM-Eval) specific test to generate a chain and verify the prompt includes the "Previous Context".
